Clinical AI & Hospital Operations Optimization at Stanford Medicine

In the Department of Pediatrics at Stanford University School of Medicine—collaborating with Profs. David Scheinker, Andrew Shin, and Terry Platchek across Stanford Medicine Children’s Health and SURF Stanford Medicine—I deliver two permissively licensed clinical and operational AI platforms on NERO GCP and Google Cloud TPUs: (1) self-service mathematical optimization for hospital decision-makers (hospital-dashboard-platform), pairing conversational LLM agents with JAX and MPAX to optimize service-unit bed assignments, BEDS/POINTS surgical scheduling, and cross-unit physician/nurse staffing; and (2) open-source clinical LLMs and longitudinal analytics (t1d-analytics) for inpatient cardiovascular intensive care (CVICU) and outpatient pediatric Type 1 Diabetes (T1D), benchmarking out-of-the-box, hospital fine-tuned, and from-scratch Gemma, MedGemma, and VaultGemma models against Gemini 2.5 Pro with on-device LiteRT deployment to Android and Chrome (informed by prior work as a former co-maintainer of Google’s MaxText JAX LLM engine).

Medical Device Creation & Point-of-Care Ophthalmic Screening

Beginning with my University of Sydney PhD in Medicine, I have designed and built inexpensive, portable medical devices and clinical diagnostic systems to bring population-scale screening for blinding eye diseases—glaucoma and diabetic retinopathy—to low-resource and point-of-care settings. This hardware-to-clinical-workflow engineering spans smartphone-based fundoscopy and direct ophthalmoscopy instrumentation (evaluated across the eFOCUS ophthalmoscopy studies and DR SPOC point-of-care diabetic retinopathy screening programs), clinician retinal image-triage platforms (@healthplatform), and automated diagnostic AI trained over 2TB+ of retinal fundus photography supported by multi-million-dollar in-kind grants from Google. Every device design, firmware/software stack, and clinical workflow is self-funded, patentless, and open-source, placing diagnostic hardware and tooling directly in the public domain.

Development Philosophy: Rejecting Bloated, Non-Native Defaults

Guided by my software engineering philosophy—“both scaling source-code and scaling deployments are difficult; they need not be”—I engineer native, cross-platform open-source alternatives to Docker (libscript), Flutter / Kotlin Multiplatform / React Native (c-multiplatform), and single-framework ML lock-in (ml-switcheroo) across three pillars: (1) Restore Monolithic Velocity—eliminating the polyglot “synchronisation tax” via bidirectional cdd compilers that synchronize models, APIs, tests, and docs across 12+ languages with Ruby on Rails or Django speed; (2) Demystify Deployment—delivering reproducible bare-metal, VM, and cloud environments via verMan.io so containers are a choice, not a mandate; and (3) Outpace ML Fragmentation—treating entire ML frameworks as a compiler search space (kitchenSink.ai) and translating models bidirectionally across runtimes.

Deep Dive 02 Portable ML Compilers: ML Switcheroo, ODL & The zero-zoo Hierarchy 8,300+ Math Ops · Zero-Binary Shells

Overview: Research and clinical ML models often decay when hardware accelerators or Python frameworks shift. ML Switcheroo pairs static Concrete Syntax Tree (CST) rewriting over an Operation Definition Language (ODL) with pure-Python zero-* frontend shells—translating and verifying over 8,300 mathematical operations across PyTorch, JAX, Flax, Keras, TensorFlow, Apple MLX, StableHLO, and GPU assembly (NVIDIA SASS, AMD RDNA).

Problem Models written for one accelerator or API (e.g., eager PyTorch on NVIDIA CUDA) require manual rewrites to run on Cloud TPUs (JAX) or Apple Silicon (MLX).
Approach Separates mathematical meaning from framework syntax via an execution-free CST/ODL hub and dependency-free zero-* API shells lowered by ml-switcheroo-compiler.
Outcome Automated bidirectional translation and numerical parity verification (zero-zoo) across 6+ runtimes without multi-gigabyte binary lock-in.

Deep Dive 03 Compiler Driven Development (CDD): 12-Language AST Synchronization 12+ Languages · Zero Schema Drift

Overview: Multi-team health and cloud platforms routinely suffer integration bugs when database schemas, backend routes, and mobile/web SDKs drift out of sync. CDD replaces manual glue code with bidirectional, AST-aware compilers (cdd-*) spanning 12+ languages (C, C#, C++, Go, Java, Kotlin, PHP, Python, Ruby, Rust, Swift, TypeScript) coordinated around a canonical OpenAPI 3.0 intermediate representation.

Problem Hand-maintaining SQL ORMs, REST routes, CLI flags, and client SDKs across Python, Rust, C, and TypeScript introduces silent schema mismatches.
Approach Parses and emits native Abstract Syntax Trees (preserving docstrings and comments) through one lossless IR orchestrated by cdd-engine.
Outcome Updating a data model in any supported language automatically updates SQL migrations, API servers, and typed client SDKs across the entire stack.

Deep Dive 05 LibScript: Reproducible Toolchains, Offline Installers & Multicloud HA 304+ Toolchains · 7+ OS Families

Overview: Research labs, regulated hospitals, and cloud teams struggle with conflicting version managers (nvm, pyenv), mandatory Docker daemons, and vendor-locked cloud scripts. LibScript (verMan.io) unifies software delivery in pure, zero-dependency POSIX /bin/sh and Windows .cmd/.ps1—scaling one declarative JSON manifest from local user sandboxes to air-gapped Windows .msi / VM / Unikernel images and fenced high-availability database & TPU clusters.

Problem Reproducing identical software stacks across developer laptops, air-gapped enterprise/clinical servers, and cloud GPU/TPU fleets usually requires heavy agents or containers.
Approach Executes 304+ declarative package recipes via native OS shells governed by JSON Schemas, a Tarjan cycle-breaking solver, and 2x idempotency gates.
Outcome One manifest provisions local non-root toolchains, exports offline .msi/qcow2/UKI images, or deploys fenced Patroni PostgreSQL HA and TPU fleets across 7+ OSes.
